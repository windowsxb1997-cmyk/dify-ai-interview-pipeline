# 面试问答：你用 AI 解决的最有趣/最有价值的场景

> 面试题：简单描述 1 个你认为你用 AI 解决的最有趣/最有价值的场景（背景、解决什么问题、用了什么工具、结果如何）
> 口播时长：约 2 分钟

## 口播版

**背景**：我之前在一家耳机公司做用户研究，公司开拓北美市场，需要访谈「在健身房戴头戴式耳机」的北美用户，了解他们的爽点和痛点。但北美访谈的招募和每小时费用远高于国内，一个 8-10 人的小样本研究，招募加访谈动辄数万元、周期两三周。

**解决什么问题**：我想验证「LLM 能不能把用户研究里最贵的三个环节降下来」——招募初筛、访谈执行、逐字稿分析。其中分析环节最痛：一份 45 分钟的英文逐字稿，研究员手动提炼画像、痛点、情感倾向，通常要花 2-3 小时，且不同研究员的分析口径不一致。

**用了什么工具**：我在自部署的 Dify 平台上设计了一套工作流系统，模型用通义千问，数据存在飞书多维表格。以最有代表性的「单场访谈分析」工作流为例：研究员上传英文逐字稿 + 输入本场关注的关键词，工作流并行跑四个模块——代码节点做英文词频统计（精确计数不用 LLM），三个 LLM 节点分别按我设计的「用户记录模板」提取结构化画像、按关键词做情感分析（区分主动提及和被问及）、按「强信号/弱信号框架」做六项业务判断并归类用户类型。输出是给人看的中文报告（引用保留英文原文防幻觉）+ 给机器看的 JSON，供后续多场汇总。

**结果如何**：分析环节从人工 2-3 小时缩短到几分钟，且口径完全统一——因为 prompt 固化的就是我之前人工访谈用的判断框架，等于把方法论资产化了。目前单场分析链路已跑通验证，招募问卷的 AI 初筛链路也已设计完成。副产品是沉淀了一套可复用的工作流搭建规范，后续做其他市场的研究可以直接复用。

## 可能的追问 & 应答要点

| 追问 | 应答要点 |
|---|---|
| 怎么验证 AI 分析质量可靠？ | 用已人工分析过的存量访谈做对照测试，看 AI 的结论、评分与人工分析的一致性；prompt 里强制要求每个结论引用受访者原话，可逐条回溯核对 |
| 为什么不直接用 ChatGPT 对话框，要做工作流？ | 对话框是一次性的：prompt 靠人肉复制、输出格式不稳定、无法批量处理。工作流把方法论固化成资产：输入输出标准化、可复用、结果自动入库、新人零培训上手 |
| 结果里的数字怎么来的？ | （面试前用真实逐字稿掐表测一次，换成自己的真实数据；并准备好描述测试过程） |
| AI 访谈能完全替代真人访谈员吗？ | 不能，定位是"分层使用"：AI 做大规模初筛和标准化追问，真人研究员做高价值对象的深访。AI 访谈的对象一致性、不知疲倦、即时转录是优势；但建立信任、捕捉语气犹豫、临场改方向仍是人的强项 |
| 最大的难点是什么？ | 不是技术，是方法论的"翻译"——把研究员脑子里的隐性判断标准（什么算强信号、什么算痛点严重）显性化成 prompt 里的判定规则，这个过程本身也倒逼我把方法论梳理得更严谨 |
| 如果重做会改进什么？ | ① 早期就做对照测试设计，而不是先建后验；② 语音访谈环节选型更保守（实时语音 API 成本和稳定性是最大变量）；③ 给每场访谈的 AI 分析加置信度标记，低置信的强制人工复核 |

## 使用提醒

- 数字（2-3 小时 → 几分钟）是估计值，**面试前用真实逐字稿掐表换成真实数据**
- 未全部上线就如实说"分析链路已跑通、其余链路设计中"，完成度已足够，不要过度包装
